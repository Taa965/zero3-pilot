# Zero3 Pilot v0.1.0-alpha — Release Notes

Release date: **2026-09-03**  
Release tag: **`v0.1.0-alpha`**  
Distribution: **GitHub pre-release / Windows NSIS**

`v0.1.0-alpha` establishes the first public Codex-native desktop-agent baseline for Zero3 Pilot. It is an alpha development release, not a production-readiness claim.

The defining architectural rule is unchanged: **OpenAI's open-source Codex app-server is the authoritative native Agent Kernel/runtime.** Zero3 Pilot adds a desktop product layer, reviewed integration boundaries, persistence/reliability work and controlled executor/handoff infrastructure around Codex instead of replacing it with a second hidden agent loop.

## Highlights

### Codex-native desktop conversation path

The Hermes-derived Electron/React UI has a Zero3-owned typed bridge to the pinned open-source Codex app-server. The migrated path includes:

- Thread start/list/read/resume and durable conversation semantics;
- Turn start/interrupt and streaming Item projection;
- native command/file approvals and user-input prompts;
- reasoning, command, file-change, MCP, dynamic-tool, plan and web-search presentation;
- structured user input and supported local images;
- thread archive/unarchive/delete/rename/fork and active-turn steer;
- authoritative message/Turn mapping and paginated history for destructive history operations.

The Renderer is not given a generic arbitrary Codex method tunnel; new capabilities require reviewed typed surfaces.

### Durable Zero3 AppServer session identity (#49)

[PR #49](https://github.com/Taa965/zero3-pilot/pull/49) makes the persisted Zero3 conversation namespace explicit. Zero3 launches its pinned Codex child with `--session-source app-server`, lists `sourceKinds: ['appServer']`, and carries a release-blocking persistence smoke that creates two non-ephemeral Threads, materializes a first Turn on each, restarts app-server with the same `CODEX_HOME`, then requires both original IDs to remain listable and readable.

### Reproducible pinned-Codex integration

Zero3 Pilot pins the open-source Codex source and maintains deterministic overlay/replay infrastructure so Zero3 extensions and narrowly justified patches can be reviewed independently of the upstream gitlink.

CI includes real Codex build/app-server protocol smokes instead of treating the integration as a mock-only boundary.

### Context and output retention

The alpha baseline includes:

- **D1:** lossless spill/recovery for oversized plain-text tool results with bounded model-context projection;
- **D2:** deterministic pruning of oversized historical tool results only in private compaction input, with D1-backed recoverability and no mutation of authoritative Thread history.

### Remote Host reliability foundation

H0-H5 establish:

- durable local task-to-Codex identity;
- crash-safe pending Turn recovery;
- durable bounded outbox with ack-before-delete;
- strict no-overtake publication ordering;
- authenticated durable control-plane state;
- sticky leases, fencing generations and replay/terminal idempotency.

### Executor, handoff and failover foundation

The release contains:

- `zero3.pilot.executor.v1`, a provider-neutral Executor contract;
- a durable Handoff protocol with deterministic workspace/Git checkpoint evidence and an exclusive writer gate;
- failover policy with bounded retry, cooldown, circuit-breaker and recovery-first semantics;
- a Native Codex executor backed by the pinned Codex app-server, using supported account/rate-limit APIs and explicit permission forwarding without reading/copying Codex credential files.

### Bundled pinned-Codex Windows package (#51)

[PR #51](https://github.com/Taa965/zero3-pilot/pull/51) builds the exact reviewed Codex pin in release mode and places `codex.exe` under application resources at:

```text
resources/zero3-codex/codex.exe
```

Packaged mode must use that reviewed bundled binary. It does not silently switch to PATH, `@latest`, a runtime download or an arbitrary `ZERO3_CODEX_BIN` host override.

The package also carries reviewed Zero3/OpenAI Codex/Hermes legal resources and is checked with `codex.exe --version` plus a real packaged app-server JSONL smoke.

### Final release-hygiene closeout (#54)

[PR #54](https://github.com/Taa965/zero3-pilot/pull/54) closed two late release blockers discovered during final acceptance:

- the public desktop-orchestrator `codex:verify` / `codex:replay` npm commands now resolve the repository overlay tool correctly;
- the historical `zero3-web` deployment workflow is manual-only and no longer deploys merely because `main` moved.

This keeps the public release model aligned with the actual Codex-native local desktop architecture.

## Explicitly deferred: PR #48 ACP external executor

[PR #48](https://github.com/Taa965/zero3-pilot/pull/48) is **not included in `v0.1.0-alpha`**.

Its dedicated behavior gate exposed contract problems including:

- an explicit permission deny path ending as `succeeded` instead of `cancelled`;
- an ACP protocol-version mismatch being normalized as `unavailable` instead of `unsupported`.

The branch also predates the merged Native Codex R4C path and needs replay/rebase onto the authoritative stack. R4B is deferred to a later pre-release instead of weakening this alpha's security/failure semantics.

## Security model

- unsupported server-request/permission classes fail closed;
- side-effecting behavior passes reviewed permission boundaries;
- migrated core operations cannot silently route to a legacy runtime;
- external executors do not inherit task/router/handoff authority;
- Native Codex auth reuse uses supported Codex account APIs rather than token extraction or credential-file copying;
- a provider path with incorrect deny/failure semantics is deferred rather than waived into the release;
- packaged Windows builds use the reviewed bundled Codex pin instead of arbitrary runtime substitution;
- security reports use GitHub private vulnerability reporting as described in `SECURITY.md`.

## Known limitations

- This is an alpha release and is not production-ready.
- No broad external adoption is claimed.
- Some Hermes-derived backend behavior remains temporary compatibility scaffolding for UI surfaces not yet fully migrated; it is not a second native Agent Kernel.
- Development conversations created before explicit Zero3 AppServer source tagging may have been stored under Codex's `vscode` source. This alpha does not promise automatic migration of those sessions because importing all `vscode` rows could mix unrelated VS Code Codex history into Zero3.
- ACP external-agent execution is intentionally not part of this alpha.
- Remote Host -> Executor Manager/Handoff/Failover integration remains follow-up work.
- The Windows alpha is **unsigned**. Windows may therefore show SmartScreen or an unknown-publisher warning. Verify the SHA-256 from the GitHub Release record before running the installer.

## Windows installation

Use the Windows installer attached to the `v0.1.0-alpha` GitHub pre-release. The installer is intended to carry the reviewed Codex runtime itself, so users do not need to install a separate arbitrary Codex binary to provide Zero3's native Agent Kernel.
