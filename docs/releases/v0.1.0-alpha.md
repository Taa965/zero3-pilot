# Zero3 Pilot v0.1.0-alpha — Draft Release Notes

> **Draft only — not a published release.**

## What this alpha is

`v0.1.0-alpha` is intended to establish a reviewable Codex-native desktop-agent foundation, not to claim production readiness.

The defining architectural choice is simple: **OpenAI's open-source Codex app-server remains the authoritative native Agent Kernel/runtime.** Zero3 Pilot adds a desktop product layer, integration guards, persistence/reliability work and controlled executor/handoff infrastructure around that core instead of replacing it with a second hidden agent loop.

## Highlights already on `main`

### Codex-native desktop conversation path

The Hermes-derived Electron/React UI has a Zero3-owned typed bridge to the pinned open-source Codex app-server. The migrated path includes:

- Thread start/list/read/resume and durable conversation semantics;
- Turn start/interrupt and streaming Item projection;
- native command/file approvals and user-input prompts;
- reasoning, command, file-change, MCP, dynamic-tool, plan and web-search presentation;
- structured user input and supported local images;
- thread archive/unarchive/delete/rename/fork and active-turn steer;
- authoritative message/Turn mapping and paginated history for destructive history operations.

The Renderer is not given a generic Codex method tunnel; new capabilities require reviewed typed surfaces.

### Reproducible pinned-Codex integration

Zero3 Pilot pins the open-source Codex source and maintains deterministic overlay/replay infrastructure so project-specific extensions and narrowly justified patches can be reviewed independently of the upstream gitlink.

CI includes a real Codex Core Smoke that builds the pinned Codex CLI and exercises a real `codex app-server` JSONL handshake rather than treating the integration as a mock-only boundary.

### Context and output retention

The alpha baseline includes two Codex-native resilience features:

- **D1:** lossless spill/recovery for oversized plain-text tool results with bounded model-context projection;
- **D2:** deterministic pruning of oversized historical tool results only in private compaction input, with D1-backed recoverability and no mutation of authoritative Thread history.

### Remote Host reliability foundation

The H0-H5 work establishes a narrow Remote Host path while preserving Codex execution authority:

- durable local task-to-Codex identity;
- crash-safe pending Turn recovery;
- durable bounded outbox with ack-before-delete;
- strict no-overtake publication ordering;
- authenticated durable control-plane state;
- sticky leases, fencing generations and replay/terminal idempotency.

### Executor, handoff and failover foundation

The current `main` also contains:

- `zero3.pilot.executor.v1`, a provider-neutral Executor contract;
- a durable Handoff protocol with deterministic workspace/Git checkpoint evidence and an exclusive writer gate;
- failover policy with bounded retry, cooldown, circuit-breaker and recovery-first semantics;
- a Native Codex executor backed by the pinned Codex app-server, using supported account/rate-limit APIs and explicit permission forwarding without reading/copying Codex credential files.

### PR #48 — ACP external executor

[PR #48](https://github.com/Taa965/zero3-pilot/pull/48) is the formal external-executor runtime. It may be included if final integration/rebase/CI gates are clean before release. If not, it should move to the next pre-release rather than delaying the first Codex-native alpha.

Audit/POC PRs that have been superseded by formal implementations should be closed or marked clearly before the release is published.

## Security model

This project is expected to touch high-privilege local surfaces over time, so security boundaries are part of the product architecture:

- unsupported server-request/permission classes fail closed;
- side-effecting behavior must pass reviewed permission boundaries;
- migrated core operations cannot silently route to a legacy runtime;
- external executors do not inherit task/router/handoff authority;
- Native Codex auth reuse uses supported Codex account APIs rather than token extraction or credential-file copying;
- security reports should use GitHub private vulnerability reporting as described in `SECURITY.md`.

## Known limitations

This is an alpha candidate. In particular:

- the project is not production-ready;
- no broad external adoption is claimed;
- some Hermes-derived backend behavior remains compatibility scaffolding for UI surfaces not yet fully migrated;
- external-agent collaboration may remain incomplete depending on the final state of PR #48;
- Remote Host -> Executor Manager/Handoff/Failover integration is still follow-up work;
- polished release screenshots/demo and final Codex-native distribution artifacts must be produced from the actual release candidate rather than mocked for documentation.
